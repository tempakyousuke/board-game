# ボドゲひろば

URL を送るだけで友達と遊べる、オリジナルのボードゲーム集です。インストールも会員登録もいりません。スマホでも PC でも遊べます。

## あそべるゲーム

どれもこのサイトのために作ったオリジナルゲームです。ルールは各ゲームの画面の「ルール」ボタンからいつでも読めます。

| ゲーム | 人数 | 時間 | どんなゲーム |
| --- | --- | --- | --- |
| 🌊 **トウダイ** | 2〜4人 | 10〜15分 | 灯台を建て、光で海を照らす陣取り。サイコロもカードも使わない読み合い。最後の1基だけは全員同時に置く。 |
| 💎 **ごっつんこ探検隊** | 2〜6人 | 5〜10分 | 全員が同時に行き先を決めて宝石を集める。同じマスをねらうと全員はね返される。 |
| 💣 **ドカン！導火線** | 2〜6人 | 5〜10分 | 導火線の長さは3枚のカードの合計。自分が知っているのは1枚だけ。ギリギリまで火を進めて点をかせぐブラフゲーム。 |
| 🌷 **コロコロガーデン** | 2〜5人 | 10〜15分 | サイコロで花壇に種をまく。ふるほど増えるが、失敗すると全部消えるチキンレース。 |
| 🍱 **つめつめ弁当** | 2〜6人 | 5〜10分 | まわってくる手札からおかずを1つ選び、3×3 のお弁当箱につめる。何を取るか、どこに置くか、となりに何をまわすか。 |

人数が足りないときは CPU を追加できます。1人で CPU と遊んで試すこともできます。

## 手元で動かす

Node.js 20 以上が必要です。

```bash
npm install
```

```bash
npm start
```

<http://localhost:3000> を開きます。同じブラウザで別のタブを開くと別の人として入れるので、1台でも複数人のつもりで試せます。

ファイルを変えるたびにサーバーを再起動したいときは `npm run dev`、テストは `npm test` です。

## Render にデプロイする

リポジトリに `render.yaml`（Blueprint）を入れてあります。

1. このリポジトリを GitHub に push する
2. Render のダッシュボードで **New > Blueprint** を選び、このリポジトリをつなぐ
3. 内容を確認して作成する

Blueprint を使わずに Web Service を手で作る場合は、次のように設定します。

| 項目 | 値 |
| --- | --- |
| Runtime | Node |
| Build Command | `npm ci` |
| Start Command | `npm start` |
| Health Check Path | `/healthz` |

ポートは Render が渡す環境変数 `PORT` を読むので、設定は不要です。

### 知っておくこと

- **インスタンスは1つで動かしてください。** ルームやゲームの状態はサーバーのメモリに置いています。複数インスタンスに増やすと、同じルームの人が別々のサーバーにつながってしまいます。
- **再デプロイや再起動をすると、進行中のルームは消えます。** データベースは使っていません。
- **無料プランは、しばらくアクセスがないとサーバーが眠ります。** 眠っていると最初の接続に1分ほどかかります。遊んでいるあいだは、画面が数分おきにサーバーへアクセスして眠らないようにしています。
- だれもいなくなったルームは 15 分後に自動で消えます。

## しくみ

ビルド工程はありません。`npm start` だけで動きます。

```
server/
  index.js        静的ファイルの配信と WebSocket の受け口
  rooms.js        ルームの管理（参加・再接続・観戦・CPU・ゲームの進行）
shared/
  games/          ゲームのルール。サーバーが進行に使い、画面も「置いたらどうなるか」の表示に使う
  palette.js      プレイヤーの色とアイコン
  rng.js          乱数（テストではシードを固定できる）
public/
  js/app.js       画面全体の入口（URL と接続状態から出す画面を決める）
  js/net.js       WebSocket 接続。切れたら自動でつなぎ直す
  js/lobby.js     待合室
  js/game.js      ゲーム中の画面の枠（プレイヤー一覧・結果）
  js/games/       ゲームごとの盤面とルール説明
  css/style.css
test/             ルールとルーム管理のテスト（CPU 同士の対戦で最後まで進むことも確認）
```

- ゲームの進行はすべてサーバーが持ちます。画面には「その人から見える情報」だけを送るので、ほかの人の手札や選択をブラウザ側でのぞくことはできません。
- 画面は [Preact](https://preactjs.com/) と [htm](https://github.com/developit/htm) で書いていて、`node_modules` からそのまま配信しています。
- 接続が切れても席は残ります。同じブラウザで開き直せば、元の席に戻れます。別の端末から入り直したときは、観戦者として入ってから「席を引き継ぐ」を押します。
- 席を外した人の番で止まったときは、ホストがその人の名前の下に出る「CPU に1手まかせる」で進められます。
- 「たたき売り！」のように時間で進むゲームは、サーバーの時計で動きます。部屋に人がいなくなると時計は止まり、だれかが戻ると再開します。

## ゲームを追加する

1. `shared/games/` にルールを書く。次の関数を export します（既存のゲームが見本になります）。
   - `meta` — 名前・人数など
   - `setup({ n, rng })` — 初期状態を作る
   - `act(state, seat, action, rng)` — 行動を適用する。不正な行動は `GameError` を投げる
   - `view(state, seat)` — その席から見える情報だけを返す
   - `pending(state)` — いま行動待ちの席
   - `bot(state, seat, rng)` — CPU の行動
   - （時間で進むゲームだけ）`timer(state)` と `tick(state, rng)` — 何ミリ秒後に何が起きるか。`meta.realtime` を付けると、CPU には番を待たずに毎回「動くか」を聞く
2. `shared/games/index.js` に登録する
3. `public/js/games/` に盤面（`Board`）とルール説明（`Rules`）を書き、`public/js/games/index.js` に登録する
4. `public/js/ui.js` の `GAME_ART` にカバーの絵を足す

`npm test` を実行すると、登録されたゲームはすべて、CPU 同士の対戦で最後まで進むかどうかが自動で確かめられます。
